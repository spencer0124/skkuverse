# Docs index and conventions

> The index and the writing rules for the SKKUverse documentation hub. This repository
> holds cross-cutting knowledge only, and anything local to one repo belongs in that
> repo's own `docs/`.

## What belongs here

| Belongs here (cross-repo) | Does not (repo-local) |
| --- | --- |
| System boundaries and architecture diagrams | One repo's build or deploy runbook |
| Data flows that cross repo lines, such as the notice pipeline | The detailed schema of one collection, which goes to the owning repo |
| Ownership maps: who writes what | Framework-specific detail |
| ADRs whose consequences cross repos | ADRs that begin and end in one repo |

Never copy a schema or a number into this repository. This is an index and a map, so link
to the owning repo's document for detail. [Data Topology](architecture/data-topology.md) is
that map for runtime data, and [`../contracts/manifest.json`](../contracts/manifest.json)
is the machine-readable one for configuration.

## Folder structure

Adopted from skkuverse-app's convention as the workspace standard. Documents are filed by
the reader's need rather than by topic, following [Diátaxis](https://diataxis.fr).

| Folder | Reader's need | Contents |
| --- | --- | --- |
| `architecture/` | Explanation, to understand | System boundary, container view, data topology (C4) |
| `flows/` | Explanation, to understand | End-to-end flows that cross repos |
| `how-to/` | How-to, to accomplish something | Task recipes with a stated starting point |
| `decisions/` | ADR | Cross-repo ADRs, named `NNNN-kebab-title.md` |

Some catalogued documents sit outside `docs/` and follow every rule on this page.
[`../contracts/`](../contracts/) is the config-contract registry, which lives apart because
`manifest.json` is read by tooling rather than by people.
[`../conventions/`](../conventions/) holds rules that apply to every repository in the
ecosystem.

The repo-root entry points, [`../README.md`](../README.md) and
[`../CLAUDE.md`](../CLAUDE.md), are exempt from frontmatter and from the index. GitHub
renders frontmatter as a table, which does not belong on a landing page, and neither file
is a catalogued document.

## Writing rules

### 1. Frontmatter (required)

```yaml
---
title: <Title Case>
type: reference | explanation | how-to | adr
status: draft | accepted | superseded | deprecated
owner: zoyoong124@gmail.com
last-updated: YYYY-MM-DD
audience: internal | public
---
```

Required on every catalogued document, including the ones outside `docs/`. Use
`audience: public` for anything published as portfolio and `audience: internal` for
private working notes.

Update `last-updated` in the same commit that changes the body. A stale date is a lie that
costs nothing to tell.

### 2. Skeleton

Frontmatter, then exactly one `# H1`, then a `> one-line summary`, then `##` sections with
no skipped levels. Copy [`_template.md`](_template.md) to start.

The summary line is not decoration. `docs_index.py` reads it to build the index above, so a
document without one fails the build.

### 3. Point at the source, don't copy the value

Never hardcode a version, a count, or a schema field that another repository owns. When
that repo changes, this one starts lying and nothing reports it.

- Wrong: `there are 149 crawl sources`
- Right: `the source list's SSOT is skkuverse-crawler's sources.json`

The same rule covers state, not only values. Per-repo adoption status and contract counts
are generated onto the landing page rather than written there.

### 4. Diagrams

Use Mermaid by default, since GitHub renders it natively with no build step. Reach for
PlantUML or C4 sources in `diagrams/` only when Mermaid genuinely cannot express the shape.

### 5. Language and prose

English everywhere. [`../CLAUDE.md`](../CLAUDE.md) carries the policy and its one carve-out
for Korean product copy, and `tools/conventions_lint.py` enforces it.

Prose style has its own rules in [`../conventions/prose.md`](../conventions/prose.md),
enforced by [`../.vale.ini`](../.vale.ini) and `tools/prose_metrics.py`.

### 6. Filenames and formatting

Lowercase kebab-case `.md`, with ADRs as `NNNN-kebab-title.md`. Code fences always carry a
language tag. Structured facts go in tables.
